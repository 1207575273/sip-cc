# 开发与构建命令

## 环境前置

| 工具 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | LTS (≥20) | 运行前端工具链 |
| Rust | stable | 编译 Tauri 后端 |
| npm | 随 Node.js | 包管理 |

首次克隆后安装依赖：

```bash
npm install
```

---

## 开发模式

```bash
npm run tauri dev
```

**执行流程：**

1. `tauri dev` 读取 `src-tauri/tauri.conf.json` 中的 `beforeDevCommand`
2. 自动执行 `npm run dev` → 启动 Vite Dev Server（`http://localhost:1420`）
3. 同时以 debug 模式编译 Rust 后端（`src-tauri/target/debug/`）
4. 弹出桌面窗口，前端代码支持热更新（HMR），Rust 改动需重启

> **产物**：不产生任何可分发文件，仅用于本地调试。
> 
> Debug 二进制位于 `src-tauri/target/debug/sip-cc[.exe]`，体积大、未压缩，不用于发布。

---

## 生产构建

```bash
npm run tauri build
```

**执行流程：**

1. `tauri build` 读取 `beforeBuildCommand`
2. 自动执行 `npm run build` → TypeScript 编译 + Vite 打包，产物写入 `dist/`
3. 以 release 模式编译 Rust（`--release`），开启完整优化
4. 使用平台打包器将前端 + 后端打包为安装程序

**各平台产物路径：**

```
src-tauri/target/release/bundle/
├── macos/          # macOS
│   ├── sip-cc.app          # 应用包（可直接运行）
│   └── sip-cc_x.x.x_aarch64.dmg  # 安装镜像
├── nsis/           # Windows
│   └── sip-cc_x.x.x_x64-setup.exe  # NSIS 安装包
├── msi/            # Windows（可选）
│   └── sip-cc_x.x.x_x64_en-US.msi
├── deb/            # Linux (Debian/Ubuntu)
│   └── sip-cc_x.x.x_amd64.deb
└── appimage/       # Linux（通用）
    └── sip-cc_x.x.x_amd64.AppImage
```

> **生产产物特点**：经 Rust release 优化、体积小、启动快，是实际分发给用户的文件。

## CI 自动构建（GitHub Actions）

**触发条件：推送到 `release` 分支**，无需打 tag，无需手动操作。

```bash
# 日常开发在 main 分支，准备发版时合并到 release 分支
git checkout release
git merge main
git push origin release
```

> `main` 分支的推送**不会**触发构建，只有 `release` 分支才会。
> 也可以在 GitHub Actions 页面手动点击 `Run workflow` 触发。

Actions 在 4 个并行 runner 上同时构建：

| Runner | 产物 |
|--------|------|
| `macos-latest` | `.dmg`（Apple Silicon arm64） |
| `macos-latest` + 交叉编译 | `.dmg`（Intel x86_64） |
| `windows-latest` | `.exe` / `.msi` |
| `ubuntu-24.04` | `.AppImage` / `.deb` |

构建完成后产物自动上传至 GitHub Releases 草稿，手动发布即可。

| Runner | 产物 |
|--------|------|
| `macos-latest` | `.dmg`（Apple Silicon arm64） |
| `macos-latest` + 交叉编译 | `.dmg`（Intel x86_64） |
| `windows-latest` | `*_x64-setup.exe` / `*.msi` / `*_portable.zip` |
| `ubuntu-24.04` | `*.AppImage` / `*.deb` |

## 发版标准流程

> **每次发版必须先升版本号**，确保生成唯一 tag，避免与旧 release 冲突。

### 第一步：升版本号

同时修改以下两个文件中的 `version` 字段（保持一致）：

- `package.json`
- `src-tauri/tauri.conf.json`

版本号遵循语义化版本（SemVer）：

| 场景 | 示例 |
|------|------|
| 新功能 | `0.2.0` → `0.3.0` |
| Bug 修复 | `0.2.0` → `0.2.1` |
| 正式发布 | `0.x.x` → `1.0.0` |

### 第二步：提交并触发构建

```bash
# 1. 在 main 分支提交所有改动（含版本号）
git add .
git commit -m "chore: bump version x.x.x → x.x.x"
git push origin main

# 2. 合入 release 分支触发 CI 构建
git checkout release
git merge main
git push origin release

# 3. 回到 main 继续开发
git checkout main
```

### 第三步：发布 Release

1. 打开 [GitHub Releases](https://github.com/1207575273/sip-cc/releases)
2. 找到对应版本的 **Draft** release
3. 确认 Assets 中包含所有平台产物
4. 点击 **Edit → Publish release** 正式发布

## 常用辅助命令

| 命令 | 说明 |
|------|------|
| `npm run dev` | 仅启动 Vite Dev Server（不含 Rust，纯前端调试） |
| `npm run build` | 仅构建前端（产物在 `dist/`） |
| `npm run tauri dev` | 完整开发模式（推荐） |
| `npm run tauri build` | 完整生产构建（推荐） |
| `npm run tauri build -- --target x86_64-apple-darwin` | macOS 交叉编译 Intel 版 |
