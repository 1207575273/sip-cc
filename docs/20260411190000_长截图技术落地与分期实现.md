## 1. 文档目的

- 把长截图从方案沉淀**落到可执行分期**：每一期**范围、交付物、验收标准、显式不做**。  
- **第一阶段（本文详写）**：**仅 Windows**；**仅在该平台开放能力与 UI**，其它平台**不展示入口、不编译平台实现或做空实现**。  
- 后续阶段仅列**方向**，避免与第一期抢 scope。

## 2. 分期总览

| 阶段 | 平台 | 能力 | 说明 |
|------|------|------|------|

## 3. 第一阶段（P1）范围

### 3.1 平台与可见性（强制）

| 项 | 要求 |
|----|------|
| **运行平台** | 仅 **Windows**（桌面端，与当前 sip-cc 目标一致） |
| **产品可见性** | **长截图按钮/图标仅在 Windows 下显示**；macOS / Linux **不展示**该入口（避免「点了无效」） |
| **实现策略** | Rust 侧：`#[cfg(windows)]` 实现滚动调度等；非 Windows 提供**统一错误类型**或**空操作**（编译通过 + 前端不调用）。前端：`navigator` / Tauri 平台判断隐藏控件。 |
| **文档与关于页** | 可在 README 写明：**长截图（滚动）目前仅支持 Windows** |

### 3.2 功能范围（P1 要做）— **手动滚动**

- **纵向**长截图：固定矩形选区（与当前截屏 overlay 选区一致）；用户**用鼠标在目标窗口内自行滚动**，再**逐帧追加**截取，最后**拼接**。  
- **入口**：符合沉淀文档 **§1.6 / §2.7**——截屏流程末段增加「长截图」。  
- **交互（采集层 + 物理层）**：点击「长截图」→ **不关闭**截屏 overlay；**采集层**为四边遮罩 + 取景框边线。仅 CSS 无法把滚轮交给下层应用，须调用 **`set_overlay_cursor_passthrough(true)`**（Tauri `set_ignore_cursor_events`），与录制选区穿透一致，使鼠标/滚轮落到 **微信等下层窗口**。采样为**上一帧截屏完成后**再间隔一段时间 `append`，避免并发截屏卡死。整窗穿透时**无法用鼠标点**工具栏，**Enter / Esc** 结束或取消（若已点进下层窗口抢走焦点，需切回 sip-cc 再按 Enter 或使用托盘后续扩展）。  
- **输出**：与现有截屏一致的单张 PNG + 剪贴板。  
- **硬上限**（当前写死在代码中，可后续接 `AppConfig`）：最大帧数、最大输出高度。

### 3.3 P1 明确不做（防 scope 膨胀）

- macOS / Linux 任何实现与入口。  
- 横向长截图、双向滚动。  
- 浏览器 CDP 整页截图。  
- **自动滚轮**长截图（`SendInput` 连续滚）：已改为手动为主；若需可另作「高级模式」恢复。  
- 复杂胶片条预览：P1 **不做**。

## 4. P1 技术模块（建议落点）

| 模块 | 职责 | P1 说明 |
|------|------|---------|
| **帧采集** | `capture_virtual_region` 固定物理矩形 | 与多显示器、虚拟桌面一致；**追加**时用户已滚好内容 |
| **合成（Rust）** | `VerticalStitcher` trait + SSD 默认实现 | 见 `snap/long_snap/` |
| **会话** | `LongSnapManualState`：`region` + `frames` | `long_snap_start` / `append_frame` / `finish` / `cancel` |
| **取景 UI** | 与截屏 overlay **同窗**：`SelectionOverlay` 内 DOM 层（四边遮罩 + 框线，事件穿透） | 无独立 `long-snap-bar` 窗口 |
| **Tauri Commands** | `long_snap_start`、`long_snap_append_frame`、`long_snap_finish`、`long_snap_cancel` | — |

### 4.1 Windows 交互策略（P1 已实现）

1. `long_snap_start`：仅建立会话（`frames` 为空），发 `long-snap-progress`（`current: 0`）；**不**隐藏 overlay、**不**开子窗口。  
2. **采样策略（已实现）**：在现有 **rdev** 全局监听中增加 **`EventType::Wheel`**，长截图会话期间将滚轮事件送入专用通道；工作线程**防抖**（约 160ms）后截当前选区，与**上一帧**在**排除左上角序号水印矩形**后计算 `mean_abs_diff_excluding_rect`，低于阈值则**丢弃**（无变化不追加）。每帧写入前在左上角绘制 **1-based 序号**（便于上下滑拼接对照）。进入模式约 280ms 后补**首帧**。**不再**使用前端定时轮询 `append`。  
3. `long_snap_finish`：取会话帧列表 → 拼接 → 保存 → 发 `long-snap-done`；前端关闭 overlay。  
4. 失败：拼接或保存错误时 `long-snap-error` + 返回错误信息。若屏幕采集仍含遮罩像素，可后续评估「捕获瞬间短暂隐藏遮罩」等策略（当前以实测为准）。

### 4.2 拼接算法（P1）

- 输入：`Vec<RgbaImage>` 或项目内等价类型，**宽度一致**（若不一致先报错或缩放一行说明）。  
- 相邻帧在**底部条带 vs 顶部条带**重叠区计算竖直位移；累加得到有效内容高度。  
- 输出单张大图；内存过大时**提前中止**并提示。

## 5. 配置与错误码（P1 建议）

| 常量（代码内） | 说明 |
|----------------|------|
| 最大帧数 | 默认 80 |
| 最大输出高度 | 默认 32000 px |

错误场景：非 Windows、无进行中会话、拼接失败、达到帧上限——前端 Toast / invoke 错误提示。

---

## 6. 验收标准（P1）

1. **仅 Windows**：非 Windows 构建运行后，**截屏界面无长截图入口**。  
2. **Windows**：在记事本或简单可滚动窗口 + 固定矩形选区下，能生成**明显长于单屏**的 PNG，接缝可接受（允许已知限制说明）。  
3. **取消**可用；**上限**生效（帧数或高度触顶时停止并提示）。  
4. **无** macOS/Linux 下无效入口或崩溃路径。

## 8. 风险与依赖（P1）

- **DPI / 缩放**：选区与 `snap` 一致，物理矩形固定。  
- **动态内容**：聊天、视频区域可能拼不齐——用户可多截或少截帧数控制。  
- **用户操作**：滑动节奏与采样间隔需大致匹配；长时间不滚动会累积高度相似的相邻帧，浪费帧数或影响拼接质量（可后续加「与上一帧相似则跳过」优化）。
