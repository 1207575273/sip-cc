# macOS 托盘单击交互方案

## 1. 问题描述

macOS 用户反馈：
- 不想用快捷键（习惯问题）
- 希望**单击托盘图标**就能触发截屏或看到菜单
- 当前行为：左键单击托盘图标**什么都不发生**，必须右键才能弹出菜单

## 2. 现状分析

### 当前代码（tray.rs 第 67-74 行）

```rust
TrayIconBuilder::with_id("main")
    .icon(app.default_window_icon().unwrap().clone())
    .menu(&menu)
    .show_menu_on_left_click(false)   // ← 禁止左键弹菜单
    .on_menu_event(move |app, event| {
        handle_menu_event(app, event.id.as_ref());
    })
    .build(app)?;
```

`.show_menu_on_left_click(false)` + 没有注册 `on_tray_icon_event` = **左键单击完全无响应**。

### macOS 平台行为惯例

| 应用 | 左键单击菜单栏图标 | 右键 |
|------|-------------------|------|
| Snipaste | 弹出菜单 | 弹出菜单 |
| CleanShot X | 弹出菜单 | 弹出菜单 |
| Alfred | 无（纯快捷键驱动） | - |
| Raycast | 弹出菜单 | 弹出菜单 |
| iStat Menus | 弹出菜单 | 弹出菜单 |

**macOS 惯例：菜单栏图标 = 左键单击弹菜单。** macOS 触控板的"右键"是双指点击或按住 Control 单击，操作成本远高于 Windows 的右键。当前设计违背了 macOS 用户的操作直觉。

### Windows/Linux 平台行为惯例

| 应用 | 左键单击托盘图标 | 右键 |
|------|----------------|------|
| Snipaste | 触发截屏 | 弹出菜单 |
| QQ | 弹出主窗口 | 弹出菜单 |
| 微信 | 弹出主窗口 | 弹出菜单 |

**Windows 惯例：左键 = 主操作（打开/触发），右键 = 菜单。**

## 3. Tauri v2 能力边界

### 可用 API

| API | 作用 | 可靠性 |
|-----|------|--------|
| `.show_menu_on_left_click(bool)` | 控制左键是否弹菜单 | 稳定 ✅ |
| `.on_tray_icon_event(handler)` | 监听 Click/DoubleClick/Enter/Leave 事件 | macOS 上 Click 事件**不可靠** ⚠️ |
| `.menu(&menu)` | 绑定右键菜单 | 稳定 ✅ |

### macOS Click 事件的已知 Bug

Tauri GitHub Issue [#11413](https://github.com/tauri-apps/tauri/issues/11413)：

> `on_tray_icon_event` on macOS only receives `Enter`, `Move`, `Leave` events. `Click` events are **not triggered**.

tray-icon 库维护者确认：

> "The left and right mouse up event is quite unreliable on macOS. It will be ignored when the menu popped up."

**结论：在 macOS 上通过 `on_tray_icon_event` 拦截左键单击来执行自定义操作（如直接触发截屏），目前不可靠。**

## 4. 方案设计

### 推荐方案：平台分化策略

根据两个平台的用户习惯差异，采用不同策略：

```
macOS:
  左键单击 → 弹出菜单（符合 macOS 惯例）
  菜单第一项 "截屏" → 单击即可截屏
  操作路径：单击图标 → 单击"截屏" = 2次点击

Windows/Linux:
  左键单击 → 直接触发截屏（符合 Windows 惯例，类似 Snipaste）
  右键 → 弹出菜单
  操作路径：单击图标 = 1次点击
```

### 实现方式

```rust
let mut builder = TrayIconBuilder::with_id("main")
    .icon(app.default_window_icon().unwrap().clone())
    .menu(&menu)
    .on_menu_event(move |app, event| {
        handle_menu_event(app, event.id.as_ref());
    });

if cfg!(target_os = "macos") {
    // macOS：左键弹菜单（平台惯例）
    builder = builder.show_menu_on_left_click(true);
} else {
    // Windows/Linux：左键触发截屏，右键弹菜单
    builder = builder.show_menu_on_left_click(false);
    builder = builder.on_tray_icon_event(|tray, event| {
        if let TrayIconEvent::Click { button: MouseButton::Left, button_state: MouseButtonState::Up, .. } = event {
            let app = tray.app_handle();
            let _ = crate::commands::snap_cmd::open_snap_overlay(app);
        }
    });
}

builder.build(app)?;
```

### 操作路径对比

| 平台 | 操作 | 当前 | 改后 |
|------|------|------|------|
| macOS | 截屏 | 右键 → 点"截屏"（需知道右键） | **左键 → 点"截屏"**（符合直觉） |
| macOS | 录制 | 右键 → 点"录制 GIF/视频" | 左键 → 点对应菜单项 |
| Windows | 截屏 | 右键 → 点"截屏" | **左键单击**（一步到位） |
| Windows | 菜单 | 右键 | 右键（不变） |

## 6. 风险评估

| 风险 | 级别 | 说明 |
|------|------|------|
| macOS 左键弹菜单后快捷键失灵 | 低 | 菜单关闭后焦点回到前台应用，全局快捷键不受影响 |
| Windows Click 事件不触发 | 低 | Windows 上 tray click 事件可靠，无已知 Bug |
| 用户习惯冲突 | 无 | 两个平台都遵循各自的惯例 |
