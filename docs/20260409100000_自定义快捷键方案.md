# 自定义快捷键方案

## 背景

当前快捷键硬编码在代码中（Windows: F1/F3，macOS: ⌘⇧1/⌘⇧3），用户无法修改。F1 和 ⌘⇧1 都是常见的系统/应用快捷键，冲突不可避免。需要让用户可以自定义快捷键。

## 现状分析

### 当前架构

```
HotkeyAction (枚举)
  ├─ Snap       → 截屏
  ├─ GifRecord  → 录制 GIF
  └─ ForceQuit  → 强制退出

按键监听
  ├─ Windows/Linux: rdev::listen → 匹配硬编码 keycode → 发送 HotkeyAction
  └─ macOS: CGEventTap → 匹配硬编码 keycode + flags → 发送 HotkeyAction
```

### 平台差异

| | Windows/Linux | macOS |
|---|---|---|
| 监听方式 | `rdev::listen` | `CGEventTap`（原生） |
| 按键表示 | `rdev::Key` 枚举 | keycode (i64) + CGEventFlags |
| 修饰键 | Ctrl, Shift, Alt | Cmd, Shift, Option, Ctrl |
| 典型快捷键风格 | `F1`, `Ctrl+Shift+S` | `⌘⇧1`, `⌘⇧S` |
| 函数键行为 | F1-F12 直接触发 | F1-F12 默认是系统功能键，需 fn 配合 |

## 设计方案

### 核心思路：能力与按键分离

```
能力（Action）     ←  配置文件  →     按键绑定（Keybinding）
  ├─ snap                              ├─ "F1"（Windows 默认）
  ├─ gif                               ├─ "Ctrl+Shift+1"（macOS 默认）
  └─ force_quit                        └─ 用户自定义
```

### 配置文件结构

`~/.sip-cc/config.json` 扩展：

```json
{
  "save_dir": "desktop",
  "custom_save_dir": null,
  "gif_fps": 10,
  "gif_max_duration_secs": 180,
  "hotkeys": {
    "snap": "F1",
    "gif": "F3",
    "force_quit": "Ctrl+C,Ctrl+C"
  }
}
```

**按键表示统一格式**：`修饰键+...+主键`

| 修饰键 | 表示 | 说明 |
|--------|------|------|
| Ctrl / Cmd | `Ctrl` | macOS 上 Ctrl 映射为 Cmd |
| Shift | `Shift` | |
| Alt / Option | `Alt` | macOS 上 Alt 映射为 Option |
| 无修饰 | 直接写主键 | 如 `F1`、`F3` |

示例：
- `F1` → Windows 上按 F1
- `Ctrl+Shift+S` → Windows 上 Ctrl+Shift+S，macOS 上 Cmd+Shift+S
- `Ctrl+C,Ctrl+C` → 连按两次 Ctrl+C（逗号分隔表示连击）

**平台透明**：用户只写一套配置，Rust 端根据平台自动映射：
- 配置里写 `Ctrl`，macOS 上实际监听 `Cmd`
- 配置里写 `Alt`，macOS 上实际监听 `Option`

### 默认配置

| 能力 | Windows/Linux 默认 | macOS 默认 |
|------|-------------------|------------|
| snap | `F1` | `Ctrl+Shift+1`（实际为 ⌘⇧1） |
| gif | `F3` | `Ctrl+Shift+3`（实际为 ⌘⇧3） |
| force_quit | `Ctrl+C,Ctrl+C` | `Ctrl+C,Ctrl+C`（实际为 ⌘C,⌘C） |

首次启动时，根据平台写入对应默认值。

### 设置界面

托盘菜单新增「快捷键设置」，点击打开 WebView 小窗口：

```
┌─────────────────────────────────────┐
│         快捷键设置                    │
│                                     │
│  截屏         [ F1            ] [改] │
│  录制 GIF     [ F3            ] [改] │
│  强制退出     [ Ctrl+C,Ctrl+C ] [改] │
│                                     │
│  点击 [改] 后按下新的快捷键组合       │
│                                     │
│         [恢复默认]    [保存]          │
└─────────────────────────────────────┘
```

**交互流程**：
1. 点击某行的 [改] 按钮 → 该行进入"监听状态"（高亮闪烁）
2. 用户按下新的快捷键组合 → 显示识别到的按键
3. 检测冲突（是否与其他能力重复）→ 冲突则标红提示，不允许保存
4. 点击 [保存] → 写入 config.json → 通知 Rust 端重新加载
5. Esc 或关闭窗口 → 放弃修改

**按键捕获**：在 WebView 中用 `keydown` 事件捕获按键，读取 `event.code` + `event.ctrlKey/shiftKey/altKey/metaKey`，组装成统一格式字符串。

### Rust 端改造

#### 1. 配置解析层（新增 `hotkey/keybinding.rs`）

```rust
/// 统一的快捷键绑定
pub struct Keybinding {
    pub ctrl: bool,    // macOS 上映射为 Cmd
    pub shift: bool,
    pub alt: bool,     // macOS 上映射为 Option
    pub key: String,   // 主键名：F1, F3, KeyS, Num1, KeyC 等
    pub double: bool,  // 是否连击（如 Ctrl+C,Ctrl+C）
}

impl Keybinding {
    /// 从配置字符串解析：如 "Ctrl+Shift+S" 或 "F1" 或 "Ctrl+C,Ctrl+C"
    pub fn parse(s: &str) -> Result<Self, String> { ... }

    /// 序列化回配置字符串
    pub fn to_string(&self) -> String { ... }
}
```

#### 2. 匹配层

Windows（rdev）：
```rust
fn matches_rdev(binding: &Keybinding, key: &rdev::Key, ctrl: bool, shift: bool, alt: bool) -> bool {
    binding.ctrl == ctrl && binding.shift == shift && binding.alt == alt
        && rdev_key_name(key) == binding.key
}
```

macOS（CGEventTap）：
```rust
fn matches_cg(binding: &Keybinding, keycode: i64, flags: CGEventFlags) -> bool {
    // Ctrl 映射为 Cmd
    let cmd = flags.contains(CGEventFlags::CGEventFlagCommand);
    let shift = flags.contains(CGEventFlags::CGEventFlagShift);
    let alt = flags.contains(CGEventFlags::CGEventFlagAlternate);
    binding.ctrl == cmd && binding.shift == shift && binding.alt == alt
        && cg_keycode_name(keycode) == binding.key
}
```

#### 3. 热重载

用户保存新快捷键后，前端调用 IPC 命令 `reload_hotkeys`，Rust 端重新读取 config.json 并更新内存中的 Keybinding 映射。

rdev/CGEventTap 的监听线程无法停止重启。用 `Arc<RwLock<HashMap<HotkeyAction, Keybinding>>>` 存储当前绑定，监听线程每次按键事件时读取最新绑定进行匹配。

```rust
static BINDINGS: Lazy<RwLock<HashMap<HotkeyAction, Keybinding>>> = ...;

// 监听回调中：
let bindings = BINDINGS.read().unwrap();
for (action, binding) in bindings.iter() {
    if matches(binding, keycode, flags) {
        tx.send(action.clone());
    }
}

// 热重载：
pub fn reload_hotkeys() {
    let config = load_config();
    let mut bindings = BINDINGS.write().unwrap();
    *bindings = parse_bindings(&config.hotkeys);
}
```

## 异常兜底设计

### 场景 1：配置文件损坏或字段缺失

**触发**：用户手动编辑 config.json 写入了非法 JSON 或非法快捷键格式

**兜底**：
- `hotkeys` 字段使用 `#[serde(default)]`，字段缺失时回退平台默认值
- `Keybinding::parse` 失败时记录 WAL 日志 `[CONFIG] 快捷键解析失败 | key=snap | value=xxx | 回退默认值`
- 整个 config.json 解析失败时全量回退 `AppConfig::default()`
- 回退后**自动重写一次 config.json**，用合法默认值覆盖损坏内容

```rust
fn load_hotkeys(raw: &Option<HotkeyConfig>) -> HashMap<HotkeyAction, Keybinding> {
    let defaults = platform_defaults();
    match raw {
        Some(cfg) => {
            let mut map = HashMap::new();
            for (action, default_binding) in &defaults {
                let parsed = cfg.get(action)
                    .and_then(|s| Keybinding::parse(s).ok())
                    .unwrap_or(default_binding.clone()); // 单项回退
                map.insert(action.clone(), parsed);
            }
            map
        }
        None => defaults, // 整体回退
    }
}
```

### 场景 2：快捷键冲突（两个能力绑了同一个键）

**触发**：用户在设置界面或手动编辑 config.json 把 snap 和 gif 设成相同的快捷键

**兜底（设置界面层）**：
- 保存前校验，冲突项标红，禁止保存
- 提示文案：「此快捷键已被"截屏"使用，请选择其他组合」

**兜底（Rust 配置加载层）**：
- 加载时检测冲突，冲突的后一项回退默认值
- 记录 WAL 日志 `[CONFIG] 快捷键冲突 | snap=F1 gif=F1 | gif 回退默认值 F3`

```rust
fn resolve_conflicts(map: &mut HashMap<HotkeyAction, Keybinding>, defaults: &HashMap<HotkeyAction, Keybinding>) {
    let mut seen: HashSet<String> = HashSet::new();
    // 按优先级顺序：snap > gif > force_quit
    for action in &[HotkeyAction::Snap, HotkeyAction::GifRecord, HotkeyAction::ForceQuit] {
        if let Some(binding) = map.get(action) {
            let key_str = binding.to_string();
            if seen.contains(&key_str) {
                // 冲突：回退默认值
                wal_log("CONFIG", &format!("快捷键冲突 | {}={} | 回退默认值", action, key_str));
                map.insert(action.clone(), defaults[action].clone());
            } else {
                seen.insert(key_str);
            }
        }
    }
}
```

### 场景 3：用户设了被系统占用的快捷键

**触发**：比如 macOS 上设 Cmd+C（复制）、Windows 上设 Ctrl+Alt+Delete

**兜底**：
- 设置界面维护一份**系统保留快捷键黑名单**：

```typescript
const SYSTEM_RESERVED: Record<string, string[]> = {
  windows: ["Ctrl+C", "Ctrl+V", "Ctrl+X", "Ctrl+Z", "Ctrl+A", "Alt+F4", "Ctrl+Alt+Delete"],
  macos: ["Ctrl+C", "Ctrl+V", "Ctrl+X", "Ctrl+Z", "Ctrl+A", "Ctrl+Q", "Ctrl+W", "Ctrl+Tab"],
};
```

- 匹配黑名单时显示警告：「此快捷键是系统常用快捷键，设置后可能影响正常操作，确定使用吗？」
- **不阻止设置**（用户可能就是想覆盖），只做提醒
- 黑名单内容可后续在 config.json 中扩展，不硬编码在 JS 里

### 场景 4：用户设了一个无法触发的快捷键

**触发**：比如 macOS 上设了单独的 F5（需要 fn+F5 才能触发），或者设了一个不存在的键名

**兜底**：
- `Keybinding::parse` 内部维护合法主键白名单（所有 F1-F12、A-Z、0-9、符号键）
- 不在白名单中 → 解析失败 → 回退默认值
- 设置界面的按键捕获只能产出白名单内的主键，从 UI 层杜绝非法输入
- macOS 上如果用户选了 F 键，提示：「macOS 上 F 键需要配合 fn 键使用，建议使用 Cmd+Shift 组合」

### 场景 5：热重载时正在录制 GIF

**触发**：用户在录制过程中打开快捷键设置窗口修改并保存

**兜底**：
- 设置界面打开时检查录制状态（调用 `get_recording_status` IPC）
- 录制中 → 所有 [改] 按钮 disable，提示「录制中无法修改快捷键」
- 防止录制中途停止键绑定变更导致无法停止录制的死锁

### 场景 6：监听线程崩溃

**触发**：rdev 或 CGEventTap 在运行中异常退出（极端情况）

**兜底**：
- 监听线程用 `catch_unwind` 包裹，panic 不扩散
- 崩溃后记录 WAL 日志 `[ERROR] [HOTKEY] 监听线程崩溃 | reason=xxx`
- 自动延迟 3 秒后重启监听线程（最多重试 3 次）
- 3 次重试都失败 → 记录日志，用户仍可通过托盘菜单操作（不依赖快捷键）

```rust
fn start_listener_with_recovery(tx: mpsc::Sender<HotkeyAction>, max_retries: u32) {
    thread::spawn(move || {
        let mut retries = 0;
        loop {
            let result = std::panic::catch_unwind(|| {
                start_platform_listener(tx.clone());
            });
            if result.is_ok() { break; } // 正常退出
            retries += 1;
            eprintln!("[sip-cc] 快捷键监听崩溃，第 {retries} 次重试");
            if retries >= max_retries {
                eprintln!("[sip-cc] 快捷键监听重试耗尽，请通过托盘菜单操作");
                break;
            }
            thread::sleep(Duration::from_secs(3));
        }
    });
}
```

### 场景 7：force_quit 快捷键被改成无法触发的组合

**触发**：用户把强制退出改成了一个永远触发不了的键

**兜底**：
- 托盘菜单的「退出」始终可用，不受快捷键影响
- `force_quit` 允许设为空字符串 `""`，表示禁用快捷键退出
- 设置界面对 force_quit 标注特殊提示：「此为紧急退出键，建议保留默认设置」

### 场景 8：config.json 文件被锁定或只读

**触发**：文件权限问题、磁盘满、杀毒软件锁文件

**兜底**：
- `ConfigManager::save()` 失败时不 panic，返回 Err 并记录 WAL 日志
- 设置界面保存失败 → 弹出错误提示「保存失败：{原因}，请检查 ~/.sip-cc/config.json 文件权限」
- 内存中的配置仍然生效（本次会话内有效），下次启动从文件读取

### 场景 9：WebView 设置窗口未正常关闭（幽灵窗口）

**触发**：类似之前 overlay 窗口的问题

**兜底**：
- 设置窗口不用 fullscreen，不用 always_on_top，是普通小窗口，风险低
- 打开设置时先检查是否已存在（`get_webview_window("hotkey-settings")`），存在则 focus 而不是重复创建
- 设置窗口关闭后不影响主应用退出（`prevent_exit` 逻辑不拦截普通窗口关闭）

## 兜底策略总览

| 场景 | 检测时机 | 兜底行为 | 日志级别 |
|------|---------|---------|---------|
| 配置损坏 | 启动/热重载 | 逐项回退默认值 + 自动重写 config | WARN |
| 快捷键冲突 | 保存/加载 | UI 阻止 + Rust 层后项回退 | WARN |
| 系统占用键 | 设置 UI | 警告提醒，不阻止 | INFO |
| 无法触发的键 | 解析时 | 白名单校验 + 回退默认 | WARN |
| 录制中修改 | 打开设置 UI | 禁用修改按钮 | INFO |
| 监听线程崩溃 | 运行时 | catch_unwind + 3 次自动重试 | ERROR |
| force_quit 失效 | 运行时 | 托盘退出按钮始终可用 | — |
| 配置文件写失败 | 保存时 | 内存生效 + 错误提示 | ERROR |
| 设置窗口残留 | 打开时 | 去重 + focus 已有窗口 | — |
