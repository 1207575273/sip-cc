# 配置文件版本与升级策略

> 日期：2026-04-10 | 实现位置：`src-tauri/src/config.rs`

---

## 1. 目的

- 在 `config.json` 中持久化**配置架构版本**，与**应用发布版本**（Rust crate 版本）对齐。
- 应用升级后若发现本地配置版本与当前程序不一致，**自动用默认配置整表覆盖并写回磁盘**，使新增配置项、默认值变更能一次性生效。
- **不侵入业务**：各模块仍只通过 `ConfigManager` 读配置，无需在业务里写 `if version { ... }`。

---

## 2. 版本来源

| 常量 / 字段 | 含义 |
|-------------|------|
| `CONFIG_FILE_VERSION` | `env!("CARGO_PKG_VERSION")`，与 `src-tauri/Cargo.toml` 中 `[package] version` 一致。 |
| `AppConfig.version` | 写入 `config.json` 的字符串，应与当前进程的 `CONFIG_FILE_VERSION` 相同。 |

发布流程中应保证 **Cargo 版本号** 与 **Tauri / 安装包版本** 一致（项目惯例已如此）。

---

## 3. 字段约定

```json
{
  "version": "0.8.3",
  ...
}
```

- **`version` 缺失**（旧版用户）：反序列化后为空字符串 `""`，视为与当前版本**不匹配**。
- **`version` 与 `CONFIG_FILE_VERSION` 任意不相等**：触发重置。

---

## 4. 加载逻辑（`ConfigManager::load_from_file`）

1. 读文件 → 反序列化为 `AppConfig`；读失败或 JSON 非法 → 使用 `AppConfig::default()`。
2. **若 `config.version != CONFIG_FILE_VERSION`**  
   - 令 `config = AppConfig::default()`（已含当前 `version`）；  
   - 将完整默认配置 **pretty 写回** `~/.sip-cc/config.json`；  
   - 返回该默认配置（**不再**对旧字段做 clamp）。
3. **若版本一致**  
   - 调用 `clamp_config_values`，对帧率、时长、预设等做范围校验与修正；  
   - 返回内存中的配置。

首次启动无文件时，`ensure_config_file()` 会写出带 `version` 的默认 JSON。

---

## 5. 重置行为说明

| 场景 | 行为 |
|------|------|
| 无 `config.json` | 内存默认配置，`ensure_config_file` 首次写入。 |
| 旧文件无 `version` | 视为不匹配 → 整表默认 + 覆盖写文件。 |
| `version` 为旧发布号（如 `0.7.0`），当前为 `0.8.3` | 整表默认 + 覆盖写文件。 |
| `version` 与当前一致 | 保留用户各项设置，仅做 clamp。 |

**注意**：版本不一致时采用**完全默认**，**不会**合并旧键；自定义快捷键、保存目录等也会恢复默认。若未来需要「保留部分键」的迁移，需在 `load_from_file` 中单独写迁移分支，本文策略仍以「简单、可预期」为主。

## 7. 扩展时检查清单

- 新增 `AppConfig` 字段：在 `Default` 中给默认值；必要时在 `clamp_config_values` 中校验。
- 发版 bump `Cargo.toml` / `tauri.conf.json` 版本：`CONFIG_FILE_VERSION` 自动变化，老用户启动即触发一次重置（若采用当前策略）。
- 若某版本**不想**重置用户配置，需改加载逻辑（例如仅当 `version` 低于某阈值才重置），属产品决策，不在默认实现中。
