# macOS 15+ 启动崩溃修复记录

## 问题现象

sip-cc v0.3.2 在 macOS 15.4.1 (Sequoia) + Apple Silicon (ARM64) 上启动后立即崩溃。

- 异常类型：`EXC_BREAKPOINT (SIGTRAP)`
- 崩溃线程：Thread 4（快捷键监听线程）
- 崩溃进程：sip-cc [60081]

## 崩溃栈帧

```
Thread 4 Crashed:
0  libdispatch.dylib    _dispatch_assert_queue_fail
2  libdispatch.dylib    dispatch_assert_queue
3  HIToolbox            islGetInputSourceListWithAdditions
4  HIToolbox            isValidateInputSourceRef
5  HIToolbox            TSMGetInputSourceProperty
6  sip-cc               rdev::macos::keyboard::Keyboard::string_from_code
7  sip-cc               rdev::macos::listen::raw_callback
```

## 根因分析

`rdev::listen` 在子线程中运行键盘事件监听。当收到按键事件时，`rdev` 内部调用 `Keyboard::string_from_code` 来将 keycode 转换为字符串，这个函数底层调用了 macOS 的 `TSMGetInputSourceProperty`（属于 HIToolbox 框架）。

**macOS 15 (Sequoia) 新增了线程断言**：`TSMGetInputSourceProperty` 和相关输入源 API 现在要求必须在主线程（main dispatch queue）上调用。`rdev::listen` 在子线程中调用这些 API，触发 `dispatch_assert_queue` 断言失败，系统直接发送 SIGTRAP 信号终止进程。

调用链路：
```
rdev::listen (子线程 Thread 4)
  → rdev::macos::listen::raw_callback
    → rdev::macos::keyboard::Keyboard::string_from_code
      → HIToolbox::TSMGetInputSourceProperty
        → libdispatch::dispatch_assert_queue → 断言失败 → SIGTRAP
```

## 解决方案

macOS 上完全不使用 `rdev`，改用原生 `CGEventTap` API（通过 `core-graphics` crate）直接监听键盘事件。

**核心区别**：
- `rdev::listen`：接收到按键后会调用 HIToolbox 做字符映射（keycode → 字符串），这一步在 macOS 15+ 必须在主线程
- `CGEventTap`：直接读取硬件 keycode 和 modifier flags，不调用 HIToolbox 字符映射，在任何线程都安全

### 平台分发策略

| 平台 | 实现 | 快捷键 |
|------|------|--------|
| Windows/Linux | `rdev::listen`（不受影响） | F1 截屏，F3 录制，双击 Ctrl+C 退出 |
| macOS | `core-graphics::CGEventTap` | ⌘⇧1 截屏，⌘⇧3 录制，双击 ⌘C 退出 |

通过 `#[cfg(target_os = "macos")]` 条件编译实现平台分发，互不影响。

### macOS CGEventTap 实现要点

```rust
// macOS keycodes（硬件扫描码，不受键盘布局影响）
const KC_1: i64 = 18;  // 数字 1
const KC_3: i64 = 20;  // 数字 3
const KC_C: i64 = 8;   // 字母 C

let tap = CGEventTap::new(
    CGEventTapLocation::Session,
    CGEventTapPlacement::HeadInsert,
    CGEventTapOptions::Default,
    vec![CGEventType::KeyDown],
    move |_proxy, _event_type, event| {
        let keycode = event.get_integer_value_field(EventField::KEYBOARD_EVENT_KEYCODE);
        let flags = event.get_flags();
        let cmd = flags.contains(CGEventFlags::CGEventFlagCommand);
        let shift = flags.contains(CGEventFlags::CGEventFlagShift);

        if cmd && shift && keycode == KC_1 { /* 截屏 */ }
        if cmd && shift && keycode == KC_3 { /* 录制 */ }

        CallbackResult::Keep
    },
);
```

### 依赖变更

```toml
[target.'cfg(target_os = "macos")'.dependencies]
core-graphics = "0.25"
core-foundation = "0.10"
```

仅 macOS 编译时引入，不影响 Windows/Linux 产物体积。

## rdev 上游状态

这是 `rdev` crate 的已知问题。macOS 15 加强了线程安全检查，`rdev` 在子线程调用 HIToolbox API 的做法不再安全。截至 2026-04-08，`rdev 0.5.x` 尚未发布针对此问题的修复版本。

## 关联修复

同时修复了 macOS 上的其他问题：

- **黑屏问题**：macOS `fullscreen(true)` 会创建独立 Space，改为用窗口尺寸覆盖屏幕
- **剪贴板问题**：macOS 上截屏写入 PNG 格式（通过 osascript），GIF 写入文件引用（POSIX file）
- **快捷键冲突**：macOS F1-F12 默认是系统功能键，改用 Cmd+Shift 组合键
- **辅助功能权限**：首次启动自动弹出系统授权引导
